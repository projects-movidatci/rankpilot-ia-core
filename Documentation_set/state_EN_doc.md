1. ## Overview:
This file defines the data structures (models) used to represent the state of a legal submission process, including both general submission details and specific data generated by a "RankPilot" engine for strategic analysis and competitive positioning.

2. ## Classes:
- `PositioningCore`: Holds core data related to the strategic positioning of a submission.
- `PositioningTier`: Defines a tier or level of strategic positioning.
- `BlindSpot`: Represents an identified issue or drawback in a submission.
- `Milestone`: Outlines a specific actionable step in a strategic plan.
- `ExecutiveSummary`: Summarizes the overall strategic assessment and key findings.
- `MetaData`: Contains metadata about the submission, such as file details, region, and deadlines.
- `AgentState`: The primary state model, unifying submission data and RankPilot analysis results.

3. ## Functions & Methods:

| Name | Parameters | Responsibility |
|---|---|---|
| `sanitize_nulls_from_php` | `data: Any` | Sanitizes data by converting `None` values in dictionaries to empty strings, likely to handle inter-system data transfer issues (e.g., from PHP). |
| `normalize_submission_type` | `value: Optional[str]` | Cleans and normalizes submission type strings to a consistent format (e.g., "Legal500", "Chambers"). |
| `sanitize_php_garbage` | `v: Optional[Any]` | Cleans potential "garbage" data structures (like `stdClass`) that might originate from PHP systems within specific fields of the `submission` model. |
| `sanitize_new_answer` | `v: Any` | Ensures that the `new_answer` dictionary has the expected keys (`target_field`, `question_text`, `answer`) and that their values are strings, converting missing or non-string values to empty strings. |
